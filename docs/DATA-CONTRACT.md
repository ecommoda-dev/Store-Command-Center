# عقد البيانات — مركز قيادة المتجر (Store Command Center)

![version](https://img.shields.io/badge/version-v1.0.0-blue)

> إلزامي قبل أي كود — `ecommoda-dashboard-builder` Step 0.
> الملف ده هو **المرجع الوحيد** لكل رقم في الأداة: مصدره، طريقة حسابه، وحدوده.

### ⚠️ فخ محسوم: صيغتان مختلفتان للوقت في نفس العمود

```
metafields_change  →  "2026-08-23 - 23:53:32"   (بتوقيت القاهرة، صيغة مخصّصة)
كل الباقي          →  "2026-08-23T13:21:08.905Z" (ISO — UTC)
```

**القرار المطبَّق (اتصحّح بعد المراجعة العدائية):** الفلترة بتوقيت القاهرة زي
فلتر الأوردرات بالظبط، فالصيغة الـ ISO لازم تتزحلق **+٣ ساعات** قبل ما ياخد منها
اليوم — من غير الزحلقة، كل نشاط من ١٢ لـ ٣ الفجر كان بيتحسب على اليوم اللي فات
في كل أرقام التحصيل والجرد والتغليف:

```sql
COALESCE(substr(datetime(substr(timestamp,1,19),'+3 hours'),1,10), substr(timestamp,1,10))
```

`datetime()` بترجع `NULL` على الصيغة المخصّصة (`"2026-08-23 - 23:53:32"`)، و`COALESCE`
بيرجّعها خام — وهي **أصلاً بتوقيت القاهرة** فما بتحتاجش زحلقة. النتيجة: الصيغتين
بيتفلتروا صح بنفس التعبير. **التوحيد على مستوى الكتابة لسه مقترح في `IMPROVEMENTS.md` بند D-1.**

## 7. قاعدة تصنيف الأوردر (إلزامية)

منقولة **حرفيًا** من `ecommoda-order-lifecycle` — مش معادة كتابتها هنا:

```
cancelledAt ≠ null + FULFILLED    → RTO
cancelledAt ≠ null + UNFULFILLED  → CANCELLED
s1 = Cancelled                    → CANCELLED   (ثانوي)
s1 = Returned                     → RTO         (ثانوي)
s1 = In-Return                    → IN_TRANSIT_BACK
s1 = Delivered + s2 = Returned + Σ currentQuantity = 0 → FULL_RETURN
s1 = Delivered                    → DELIVERED   (شامل المرتجع الجزئي والاستبدال المكتمل)
غير كده                           → IN_PROGRESS
```

**RTO و FULL_RETURN مربعين منفصلين — ممنوع دمجهم.** والنسب:

```
RTO Rate                = RTO / (Delivered + FULL_RETURN + RTO)
Post-Delivery Return    = FULL_RETURN / (Delivered + FULL_RETURN)
R/E Request Rate        = أوردرات فيها أي نشاط S2 / Delivered
```

### 🔧 تصحيح مُطبَّق في النسخة دي (كان بق معروف في لوحة الأداء v3.0.0)

`s1 = In-Return` كان بيتحسب **"مؤكد خرج للشحن"** في عدّ الأوردرات، وده مخالف صراحةً
للقاعدة 12 في `ecommoda-order-lifecycle` (الطي في `Shipped` مسموح **للفلوس فقط**،
ممنوع لعدّ الأوردرات). **في الأداة دي في مربع مستقل `IN_TRANSIT_BACK` — «قيد الإرجاع للمخزن».**

## 8. المؤشرات المعتمدة — الجدول الكامل

### 8.1 الفلوس (مستوى القطعة — `piece-level-valuation.md`)

| المؤشر | المعادلة | المصدر |
|---|---|---|
| القيمة الإجمالية | `Σ (Q × P)` لكل سطر | مرحلة 1 |
| صافي المبيعات | القطع الحيّة المُسلَّمة + البدائل المُسوّاة | 1 + 2 |
| الفاقد | ملغي + RTO + محذوف قبل الشحن + مرتجع نهائي + مرتجع استبدال | 1 + 2 |
| قيد التنفيذ | ٨ مربعات فرعية | 1 + 2 |
| **المتطابقة** | `القيمة الإجمالية = قيد التنفيذ + الفاقد + صافي المبيعات` | — |
| **تكلفة البضاعة (COGS)** | `Σ (وحدات مباعة × unitCost بالـ SKU)` | 1 + الكتالوج |
| **مجمل الربح** | `صافي المبيعات − COGS` | محسوب |
| **نسبة الهامش** | `مجمل الربح / صافي المبيعات` | محسوب |
| **تغطية التكلفة** | `وحدات ليها unitCost / كل الوحدات` | ⚠️ لو < 95% كل أرقام الهامش عليها تحفّظ ظاهر في الواجهة |
| عمق الخصم | `Σ currentTotalDiscountsSet / (صافي المبيعات + الخصم)` | 1 |
| إيراد الشحن | `Σ totalShippingPriceSet` للمُسلَّم | 1 |
| COD محصَّل | `Σ صافي الأوردرات المُسلَّمة اللي ميتافيلد `payment` فيها COLLECTED` | 1 |
| COD غير محصَّل | نفسها بـ `PENDING` | 1 |
| **COD بحالة غير معروفة** | نفسها بأي قيمة تانية أو فاضية | 1 |
| **نسبة التحصيل** | `محصَّل / (محصَّل + غير محصَّل)` — ⚠️ **«غير المعروف» مستبعد من المقام عن قصد**: إدخاله في البسط بيطلّع رقم متفائل كاذب، وإدخاله في المقام بيطلّع رقم متشائم كاذب. بيتعرض كمربع مستقل بدل ما يتبلع | محسوب |

> **الربح ده «مجمل» مش «صافي».** مفيش في الأداة: مصاريف الشحن الفعلية، الإعلانات،
> المرتبات، الإيجار. أي كلام عن «الربح الصافي» يحتاج مصادر مش موجودة في شوبيفاي —
> مقترح كامل في `IMPROVEMENTS.md` بند B-1.

### 8.2 العدّ والتشغيل

| المؤشر | المعادلة |
|---|---|
| الأوردرات | عدد الأوردرات في الفترة (تاريخ الإنشاء، بتوقيت القاهرة) |
| متوسط قيمة الأوردر AOV | `صافي المبيعات / عدد الأوردرات المُسلَّمة` |
| قطع لكل أوردر UPT | `الوحدات / الأوردرات` |
| متوسط سعر القطعة ASP | `صافي المبيعات / الوحدات المباعة` |
| نسبة التسليم | `Delivered / (Delivered + RTO + FULL_RETURN)` |
| نسبة الإلغاء | `CANCELLED / كل الأوردرات` |
| **نسبة المرتجع (لكل موديل/براند/فئة)** | `وحدات مرتجعة / (وحدات مباعة + وحدات مرتجعة)` — المقام هو **كل اللي خرج**، عشان الموديل اللي رجع كله يطلّع 100% مش ∞ |
| **نسبة طلب إرجاع/استبدال** | `(استبدال + مرتجع جزئي + مرتجع كامل + قيد الإرجاع) / المُسلَّم` — مؤشر **جودة منتج**، أوسع من نسبة المرتجع لأنه بيشمل نشاط S2 اللي مبيغيّرش تصنيف الأوردر |
| زمن التأكيد | `printing_time_s1 − createdAt` (تقريبي — بيتكتب فوق عند إعادة الطباعة) |
| زمن التغليف | `s1_packing_date_time − printing_time_s1` |
| زمن الخروج للشحن | `s1_packing_date_time − createdAt` |
| طوابير الانتظار | عدد + **أقدم عمر** لكل حالة مؤقتة (`New Order`, `WhatsApp-Confirmed`, `WhatsApp-CANCELLED`, `Pending Edit`, `Confirmed + Edit`) |
| Ready + Fulfilled | **محاولة تسليم مكررة** — مفصولة عن أول إرسال (القاعدة 5) |

### 8.3 الجغرافيا والمناديب

| المؤشر | المعادلة | حد أدنى للعرض |

| هيكل الـ SKU | `STYLE / Color / Size` | 1,355 من 1,357 بالشكل ده — الباقي بيتوسم «SKU غير قياسي» |
| معدل التصريف Sell-Through | `الوحدات المباعة في الفترة / (المخزون الحالي + الوحدات المباعة)` | — |
| أسابيع التغطية | `المخزون الحالي ÷ (الوحدات المباعة ÷ عدد أسابيع الفترة)` | ∞ لو مفيش مبيعات |
| قيمة المخزون بالتكلفة | `Σ (الكمية × unitCost)` | الفاريانتس بدون تكلفة بتتعلّم |
| المخزون الراكد | مخزون > 0 و**صفر مبيعات** في الفترة | الفترة معروضة صراحةً |
| مقاسات مكسورة | مقاس أساسي (≥15% من منحنى المبيعات) نافد بينما الستايل لسه فيه مخزون | — |
| نقطة إعادة الطلب | `(متوسط المبيعات اليومية × مهلة التوريد) + مخزون أمان` · `SS = Z × σ_d × √LT` · Z=1.645 لخدمة 95% | مهلة التوريد إعداد في الواجهة (افتراضي 21 يوم) |
| معدل مرتجع الـ SKU | `الوحدات المرتجعة / الوحدات المباعة` | تنبيه **بس** لو اختبار نسبتين (z) معنوي و**≥ 30 وحدة مباعة** |

## 9. قواعد محرك الرؤى (§INSIGHTS)

كل رؤية كائن ثابت الشكل:

```js
{ id, sev: 'critical'|'watch'|'info', domain, title, why, action, impact, evidence, conf }
```

### المبادئ الأربعة (غير قابلة للتفاوض)

1. **الترتيب بالفلوس مش بالنسبة.** `impact` بالجنيه، والترتيب `impact × وزن الخطورة`.
   انخفاض 60% في قناة بتجيب 3,000 ج.م أقل أهمية من انخفاض 6% في قناة بتجيب 400,000.
2. **حد أدنى للعيّنة قبل أي تنبيه.** نسبة على أقل من الحد = **"لسه بدري"**، مش تنبيه
   ومش صمت. (Wilson score interval — التداخل بين الفترتين = مفيش تنبيه.)
3. **سقف صارم على العدد.** 3 «حرجة» بحد أقصى في الأعلى، والباقي في تاب الرؤى.
4. **كل رؤية بتقول تعمل إيه.** «راجع» مش إجراء. «اقفل COD في المنيا للعميل الجديد» إجراء.

### الحدود الإحصائية المستخدمة

| الأداة | الاستخدام | الحد |
|---|---|---|
| Wilson score interval | أي **نسبة** (RTO، إلغاء، مرتجع، تحويل) | 95% — تنبيه بس لو الفترتين **مش متداخلتين** |
| اختبار نسبتين (two-proportion z) | شريحة (محافظة/مندوب/SKU) مقابل المتوسط العام | `|z| > 1.96` + حد أدنى للعيّنة |
| Robust z (MAD) | شذوذ في السلسلة اليومية | `|M| > 3.5` مقابل **نفس يوم الأسبوع** في آخر 4 أسابيع |
| CUSUM | تحديد **تاريخ** بداية التغيّر | `k = 0.5σ`, `h = 4σ` |
| مقارنة موسمية | كل مقارنة يومية بتتم مع **نفس يوم الأسبوع** | لأن السبت ≠ الثلاثاء |

> اخترنا الحدود دي عن قصد بدل نماذج تنبؤ (Prophet/SARIMA): المكسب في الدقة مايستاهلش
> اعتماد خارجي جوه Worker، و«متوسط آخر ٤ نفس-أيام + MAD» بيمسك الغالبية العظمى من
> الحالات الحقيقية. المرجع الكامل والبدائل → `IMPROVEMENTS.md` بند C-3.

## 10. الكاش والتحديث

```
مفتاح البيانات    : scc:store_command_center:v1:data:{from}:{to}
مفتاح الميتا      : scc:store_command_center:v1:meta:{from}:{to}
مفتاح الكتالوج    : scc:store_command_center:v1:catalog
مفتاح D1          : scc:store_command_center:v1:ops:{from}:{to}
مفتاح فترة المقارنة: scc:store_command_center:v1:prev:{from}:{to}   (نسخة **مصغّرة**: KPI والمربعات بس)

dateTo <  النهارده  →  كاش دائم (النطاق مقفول، مستحيل يتغيّر)
dateTo >= النهارده  →  expirationTtl = 900 (15 دقيقة)
الكتالوج            →  expirationTtl = 21600 (6 ساعات) — مستقل عن أي نطاق
```

* **مفيش Cron. خالص.** التحديث بحدثين بس: زرار التحديث، أو تغيير الفترة.
* **مفيش كتابة جزئية.** الكتابة بعد آخر صفحة تنجح. أي صفحة تفشل = الطلب كله يفشل.
* **مفيش إعادة قراءة من KV بعد الكتابة** (نافذة الاتساق 60 ثانية).
* `CACHE_VERSION = 'v1'` — **يزيد مع أي تغيير في قائمة الحقول**.
* **فترة المقارنة ليها كاش مصغّر خاص بيها.** من غيره كل ضغطة تحديث كانت بتجيب
  الفترة الحالية **والسابقة** من شوبيفاي — يعني ضِعف التكلفة على كل نداء بينما
  الفترة السابقة شبه دايمًا **مقفولة ومستحيل تتغيّر**. المفتاح ده بيتكتب دايم لو
  النطاق مقفول، و`clear_cache` بيمسحه مع نطاقه.
* **السلسلة اليومية مسقوفة عند ٤٠٠ نقطة** (`seriesTruncated: true`) — الرسم بيوقف
  عند الحد والواجهة بتقول كده ببانر. الأرقام الإجمالية والجداول مش متأثرة.

> ⚠️ **نتيجة مقصودة:** نطاق مقفول متكاش = **التكلفة والهامش متجمّدين وقت الحساب**.
> لو اتعدّلت تكلفة منتج بأثر رجعي، لازم «تحديث» أو `clear_cache` للنطاق ده.
> ده مكتوب في نافذة «عن الأداة» عشان محدش يقراه كباج.

## 10-ب. عقد نداءات السجل (`get_logs*`)

تاب السجل هو **المكان الوحيد** في الأداة اللي فيه نص جاي من المستخدم بيوصل لـ SQL،
فالعقد هنا صارم:

| الباراميتر | الشكل | القاعدة |
|---|---|---|
| `tool` · `employee` · `type` | قائمة مفصولة بفواصل (`a,b,c`) أو `all` | كل قيمة بتتربط كـ **placeholder منفصل** في `IN (?,?,…)`. مفيش أي نص بيتحط في نص الـ SQL. الحد ٦٠ قيمة للفلتر الواحد |
| `search` | نص | `LIKE` على `order_name` · `notes` · `sku` — مربوط برضه |
| `sort` | اسم عمود | **whitelist بس**: `timestamp` · `tool` · `type` · `employee` · `order_name` · `sku`. أي اسم تاني بيرجع لـ `timestamp` |
| `dir` | `asc` \| `desc` | أي حاجة تانية = `DESC` |
| `limit` · `offset` | رقم | `limit` مسقوف عند ١٠٠ |

* **الفلترة والترتيب بيحصلوا في SQL على السجل كله** — مش على الصفحة المعروضة.
  ده مش تفصيلة أداء: الجدول مقسّم صفحات على السيرفر، فلو الفلترة اتعملت على
  الصفحة، «النتائج: ١٠٠» والتصدير هيبقوا **رقمين كاذبين**.
* `get_logs_export` بيصدّر كل النتائج المطابقة (سقف ٢٠٠٠) مش الصفحة الحالية.
* `get_log_tools` بيرجّع قيم الفلاتر الثلاثة **بعدّاداتها** من D1 مباشرةً.
* **انحراف مقصود موثّق:** الأداة قراءة-فقط فسجلها الخاص فيه دخول/خروج بس (وده
  مستبعد في الـ SQL أصلاً). وبما إنها شاشة المدير، السجل بيعرض **كل الأدوات**
  افتراضيًا بدل أداة واحدة.
